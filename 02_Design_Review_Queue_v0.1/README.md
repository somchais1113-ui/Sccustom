# SCCUSTOM · คิวตรวจแบบ Revision v0.1

ชุดติดตั้งสำหรับทดลองใช้ภายใน Google Workspace บริษัท แยกจาก Print Studio เดิม ไม่ต้องแก้หน้าเว็บเดิม และไม่มีการส่งอีเมลหรือปล่อยงานผลิตอัตโนมัติ

## Workflow

1. **Sale** ใน Print Studio เปิดหัวข้อ «ส่ง Design ตรวจรายละเอียด» และดาวน์โหลด ZIP ชื่อท้ายด้วย `-design-review.zip` อัปโหลดเป็นไฟล์ใหม่ในโฟลเดอร์รับงาน แล้ววางลิงก์ในหน้า «ส่งแบบเข้า Design» พร้อมเลขงานและรุ่นปากกา
2. **Apps Script** ออกเลข Revision ของคิวตามเลขงานและบัญชี Sale สร้างสำเนา ZIP แยกใน Drive และเพิ่มรายการ «รอตรวจ» ใน Sheets
3. **Design** เปิดคิว เลือก «ดูประวัติ Revision» และเปิด ZIP ฉบับตรวจจากลิงก์ในรายการ บันทึก «ส่งกลับแก้» พร้อมจุดที่ต้องแก้ หรือ «Design ตรวจผ่าน» ระบบบันทึกอีเมลผู้ตรวจและเวลาอัตโนมัติ
4. หากแก้แบบ ให้ Sale ใช้เลขงานเดิมและ **บัญชีเดิม** อัปโหลด ZIP ฉบับแก้เป็นไฟล์ใหม่ แล้วส่งตรวจอีกครั้ง ฉบับล่าสุดเริ่มที่ «รอตรวจ» เสมอ โดยผลและไฟล์ก่อนหน้ายังอยู่ในประวัติ

เลข Rev. ใน Print Studio กรอกอ้างอิงได้ แต่ไม่ใช่เลข Revision ของคิว งานเลขเดียวกันจาก Sale คนละบัญชีจะแยกคนละประวัติ รุ่นนี้ยังไม่รองรับการเปลี่ยนเจ้าของงานหรือผู้ส่งสำรอง

สถานะ **Design ตรวจผ่าน** ใช้กับ ZIP ใน Revision นั้นเท่านั้น ไม่ได้แปลว่าลูกค้าอนุมัติหรือปล่อยผลิต หากเปิด Revision ใหม่ ระบบไม่ยกสถานะเดิมมาทับฉบับใหม่

คิวนี้ยังไม่ซิงก์สถานะกลับไป Print Studio เมื่อ Design ลงผลแล้ว Sale จึงยังต้องจัดการขั้นตอน «ได้รับผลตรวจแล้ว» ใน Print Studio ตามผลของ Revision นั้น หากผลเป็น «ส่งกลับแก้» ให้แก้แล้วส่ง Revision ใหม่ก่อนดำเนินการต่อ

## ตั้งค่า Google Workspace

1. สร้าง Google Sheet ว่างสำหรับทะเบียนคิว แล้วคัดลอก ID จาก URL ช่วงหลัง `/spreadsheets/d/` ก่อน `/edit` จำกัดสิทธิ์แก้ไข Sheet ให้ผู้ดูแลและบัญชีที่ Deploy เท่านั้น ทีมใช้งานผ่าน Web App
2. สร้างสองโฟลเดอร์แยกกันบน Drive และคัดลอก ID จาก URL ช่วงหลัง `/folders/`

   | โฟลเดอร์ | สิทธิ์ที่แนะนำ |
   | --- | --- |
   | รับงาน | Sale ที่เกี่ยวข้องอัปโหลด ZIP ได้ บัญชีที่ Deploy อ่านและคัดลอกไฟล์ได้ |
   | สำเนาตรวจแบบ | บัญชีที่ Deploy เพิ่มไฟล์ได้ Design เปิดและดาวน์โหลดได้โดยไม่มีสิทธิ์แก้ไฟล์ Sale ไม่ต้องมีสิทธิ์เข้าถึง |

   ใช้โฟลเดอร์แยกจากที่ทุกคนเป็น Editor โดยเฉพาะเมื่อโฟลเดอร์สืบทอดสิทธิ์จาก Shared Drive ตรวจสิทธิ์ที่มีผลจริงทั้งสองโฟลเดอร์และไม่เปิดแบบ «ทุกคนที่มีลิงก์» ผู้ที่มีสิทธิ์เข้าถึงโฟลเดอร์รับงานอาจเห็น ZIP ของคนอื่นได้แม้หน้า Web App จะจำกัดงานตามเจ้าของ หากงานลูกค้าแต่ละรายต้องแยกสิทธิ์จากกัน ให้ใช้โฟลเดอร์รับงานแยกเฉพาะทีมทดลองก่อน

3. ไปที่ [script.google.com](https://script.google.com/) จากบัญชีบริษัท สร้าง **New project** แบบ standalone ตั้งชื่อ `SCCUSTOM Design Review Queue`
4. คัดลอก `apps-script/Code.gs` ใส่ไฟล์ Code.gs ในโครงการ กด **+ → HTML** ตั้งชื่อ `Index` แล้วคัดลอก `apps-script/Index.html` ใส่ไฟล์นั้น
5. ที่ **Project Settings** เปิด **Show "appsscript.json" manifest file in editor** แล้วแทนที่ไฟล์ manifest ด้วย `apps-script/appsscript.json` กดบันทึกและตรวจว่า **Services** แสดง **Drive API (v3)** หากโครงการผูกกับ Standard Google Cloud project ให้เปิด Drive API ใน Cloud Console ของโครงการนั้นด้วย
6. ใน **Project Settings → Script Properties** เพิ่มค่าต่อไปนี้

   | ชื่อ | ค่าที่ใส่ |
   | --- | --- |
   | `SHEET_ID` | ID ของ Google Sheet |
   | `INTAKE_FOLDER_ID` | ID โฟลเดอร์รับงาน |
   | `ARCHIVE_FOLDER_ID` | ID โฟลเดอร์สำเนาตรวจแบบ |
   | `WORKSPACE_DOMAIN` | โดเมนบริษัท เช่น `example.com` ไม่ใส่ @ |
   | `SALES_EMAILS` | อีเมล Sale ในโดเมน คั่นด้วยจุลภาค |
   | `DESIGN_EMAILS` | อีเมล Design ในโดเมน คั่นด้วยจุลภาค |

7. ใน Editor เลือก `setup_` แล้วกด **Run** จากบัญชีที่จะ Deploy ทำขั้นตอนยืนยันสิทธิ์ให้ครบ และตรวจว่า Sheet มีแท็บ `SCCUSTOM_ReviewLog` พร้อมหัวตาราง หากใช้แท็บเดิมให้สำรองก่อนและไม่เปลี่ยนชื่อหรือสลับคอลัมน์
8. เลือก **Deploy → New deployment → Web app** ตั้ง **Execute as → Me** และ **Who has access → ผู้ใช้ในองค์กร/โดเมนบริษัทเท่านั้น** แล้ว Deploy คัดลอก URL ที่จบด้วย `/exec` ให้ทีม ห้ามปรับเป็น Anyone เพื่อแก้ปัญหาเข้าไม่ได้
9. เปิดจากบัญชี Sale และ Design จริงคนละบัญชี แล้วทำรายการทดสอบด้านล่าง หากระบบอ่านอีเมลบัญชี Workspace ไม่ได้ ให้ผู้ดูแลตรวจนโยบายองค์กรและการตั้งค่า Deploy อย่าแทนที่อีเมลผู้ตรวจด้วยข้อมูลที่กรอกเอง

## เช็กลิสต์ก่อนเริ่มใช้จริง

- [ ] Sale ส่ง ZIP ตัวอย่างจาก Print Studio แล้วเห็น Rev.01 ขึ้นในคิว และกดส่งซ้ำไฟล์เดิมด้วยข้อมูลเดิมไม่สร้าง Rev.02
- [ ] Design เปิด ZIP สำเนาได้และกด «ส่งกลับแก้» พร้อมข้อความ เช่น «เพิ่มช่องไฟระหว่างโลโก้กับชื่อ»
- [ ] Sale เห็นผลตรวจ ส่ง ZIP ฉบับแก้เป็นไฟล์ใหม่ด้วยเลขงานเดิม แล้วเห็น Rev.02 เป็น «รอตรวจ»
- [ ] Design บันทึก «Design ตรวจผ่าน» ให้ Rev.02 แล้วเปิดดูประวัติได้ทั้งสองฉบับ พร้อมผู้ตรวจและเวลา
- [ ] Sale อีกบัญชีไม่เห็นรายการของเจ้าของงานเดิมใน Web App และบัญชีที่ไม่อยู่ในรายการสิทธิ์เข้าใช้คิวไม่ได้
- [ ] ลองบนมือถือด้วยบัญชีบริษัทจริงและตรวจว่าปุ่มเปิด ZIP ถูกสิทธิ์ ไม่ขอให้เปิดโฟลเดอร์เป็นสาธารณะ

## การดูแลระบบ

- หน้า “งานล่าสุด” แสดงเฉพาะ Revision ล่าสุดของแต่ละงาน ผลเก่ายังดูได้ใน “ประวัติ Revision” และไม่สามารถลงผลตรวจซ้ำหรือย้อนหลังผ่านหน้าเว็บได้
- Sheet เก็บเหตุการณ์ส่งตรวจและลงผลแบบเพิ่มแถว ไม่ควรแก้ เรียงย้าย หรือลบแถวในแท็บทะเบียน ให้ใช้หน้าคิวหรือทำรายงานในแท็บแยก (ผู้ดูแล Google Sheet ยังมีสิทธิ์แก้ต้นทางได้ จึงไม่ใช่ทะเบียนกันการแก้ไขโดยผู้ดูแล)
- ZIP สำเนาแยกจากไฟล์ต้นทาง การแก้หรือแทนที่ไฟล์ต้นทางหลังส่งไม่เปลี่ยนสำเนา ส่วนการบันทึกผล Design ตรวจว่าไฟล์สำเนายังอยู่ในโฟลเดอร์และ checksum ตรงกับตอนส่ง
- คัดลอกไฟล์กับเขียน Sheet เป็นคนละขั้น หากคัดลอกแล้วเขียน Sheet ไม่สำเร็จ อาจเหลือไฟล์สำเนาที่ไม่ผูกกับทะเบียน ให้ผู้ดูแลเทียบ ID ของไฟล์กับคอลัมน์ `Snapshot ID` ก่อนจัดการ ไม่ใช้ไฟล์ที่ไม่ปรากฏในประวัติเป็นหลักฐานอนุมัติ
- โปรแกรมตรวจข้อมูลกำกับไฟล์จาก Drive แต่ไม่แตก ZIP ไม่ตรวจเส้นบาง ช่องไฟ หรือความพร้อมผลิตแทน Design
- รุ่นนี้เหมาะกับทีมทดลองขนาดเล็ก ระบบอ่านทะเบียนเพื่อสร้างคิว หากปริมาณโตจนการค้นหาช้า ให้เก็บข้อมูลล่าสุดด้วยดัชนีหรือย้ายไปฐานข้อมูล
- ยังไม่ได้ Deploy หรือทดสอบสิทธิ์ Google Workspace ของบริษัท ผ่านการทดสอบกติกาคิวกับ Sheets/Drive จำลอง รันซ้ำได้ด้วย Node.js 18 ขึ้นไป โดยไม่ต้องติดตั้ง dependency

```bash
node --test tests/review-queue.test.cjs
```

คู่มืออ้างอิง Google [Web apps](https://developers.google.com/apps-script/guides/web), [Advanced Drive service](https://developers.google.com/apps-script/advanced/drive) และ [Session.getActiveUser()](https://developers.google.com/apps-script/reference/base/session)
